# ACT 学习计划

## 目标与当前位置

本阶段在 ImitationPolicyLearning 中学习 Action Chunking with Transformers（ACT），建立从专家示范到动作块预测、再到环境反馈的完整理解。先从 ACT 自身的问题与结构出发，再与已有生成式策略比较。

> 问题与整体地图 → VAE/CVAE 最小基础 → 真实数据与配置 → 网络与训练目标 → 动作生成与执行 → 有界训练与恢复 → 闭环诊断 → 收尾

已有基础：状态 BC、二维 DDPM、CNN、D2L Ch10；Diffusion Policy DP0–DP8 和二维 Conditional Flow Matching F0–F6 已按各自的机制学习与有界验证范围收尾。前序完成不代表掌握 ACT，也不代表已有可靠本地 DP 策略。

本阶段的完成标准是：能解释核心机制并处理适用的新例子，且真实 batch、参数更新、保存恢复和闭环接口具有运行证据。不把高成功率、长程训练、全论文性能复现或全部理论证明设为结业条件。

当前入口为 A0。文件与目录的初始化仅表示计划就绪，所有 gate 均未通过，尚无 ACT 实验结果。

## 已确认的首轮预算

| 项目 | 约定 |
| --- | --- |
| 训练 seed | 0，只有一个训练 seed |
| 固定 batch 诊断 | 最多 500 次参数更新，可在预声明标准满足后停止 |

batch size、chunk_size、n_action_steps、optimizer、归一化、backbone 权重与验证窗口等值，在 A2/A5 运行前根据实际接口冻结并写入配置。先采用能运行的小 batch；若资源不足先说明并调整配置，不擅自增加更新预算。

## A3：网络与训练目标

本轮问题：真实 batch 如何产生动作预测和训练信号？

- 沿 `ACTPolicy.forward → ACT.forward → loss → backward` 追踪视觉特征、潜变量编码、策略 encoder/decoder、query 和动作输出。
- 记录关键 token 来源、形状、位置编码及 attention 联系；使用实际源码检查，而不是从模块名称推断执行顺序。
- 用真实 batch 核对动作重建项、padding mask、KL 与总 loss 的数值关系和 reduction 口径。
- 检查预期训练模块的有限梯度；本关单次 forward/backward 不调用 optimizer 更新参数。
- 明确验证 batch 含专家动作时是否仍调用潜变量编码器；这种 loss 与部署时只给观测的输出不是同一种测试。

出口：能解释输入来源、信息/梯度去向与损失构成；手工复算和源码计算口径一致。记录实际 padding 比例，不把不同 averaging 方式误写为等价。

## A4：动作生成与执行

本轮问题：动作块如何变成环境中的逐步动作？

- 沿 `select_action → model → unnormalize → action queue → env.step` 追踪部署路径。
- 检查部署中是否携带专家 action，明确潜变量取值、eval 模式、生成长度和实际执行长度。
- 解释队列何时查询模型、何时取动作、episode reset 清空什么状态。
- 单独学习 temporal ensembling；用带时间标记的人工动作块验证重叠预测如何对应同一个环境时刻、如何加权及 reset。

出口：能用具体时间轴解释缓存与反馈。人工动作块实验用于检查索引与聚合，不声明能提高任务成功率。首轮真实闭环默认使用普通动作队列，temporal ensembling 不增加额外 rollout 预算。

## A5：有界训练、验证与恢复

本轮问题：参数是否确实更新？记录的 loss 与保存状态是否支持复核？

- 在执行前声明固定 batch 诊断的比较条件和通过标准。考虑随机潜变量与 dropout：使用可复核的固定评估条件或记录多次测量，不要求 KL 与总 loss 都趋于零。
- 固定 batch 最多 500 次更新，记录重建项、KL、总 loss、梯度异常与更新前后参数变化。
- 随后真实 DataLoader 执行 200 次更新；按 episode 隔离训练/验证，仅使用训练统计量。
- 保持验证样本和测量条件可比较，说明验证范围和潜变量路径；不把有限验证子集写成全数据集泛化。
- 保存权重、optimizer、随机状态、数据游标、实际配置和版本指纹；用短段分割恢复与连续执行检查新进程恢复，计入既定更新预算。
- 日志与 checkpoint 明确对应，配置中写有但未被实际执行的字段不得作为运行事实。

出口：诊断有学习证据，训练无未处理的 NaN/Inf，参数更新可核实，恢复状态和重新加载推理通过。不因 loss 下降认定闭环任务已解决。任何未通过项保留并注明原因，不自动勾选本关。

## A6：闭环诊断与方法对照

本轮问题：学习到的动作输出能否经过正确接口作用于环境？哪些现象可以解释？

- 使用本地 checkpoint，seed 0，执行 1 个最多 300 步的 Push-T episode。
- 保存 success、最大 coverage、terminated/truncated、episode 长度、规划延迟、动作变化和视频/轨迹；记录硬件和实际执行配置。
- 计时区分首次冷启动和后续规划；普通队列中的取动作耗时不与完整模型查询耗时混淆。
- 对照 DP 的训练目标、结构、条件窗口、动作生成与执行组织。成本或任务观察注明 checkpoint 来源、硬件、预算和口径差异；已有历史延迟不可直接当配对实验。
- 若任务失败，先区分接口异常与策略行为；缺少证据时保留未知根因。

出口：闭环接口可以运行，完整 episode 结果可追溯，能解释其证据边界。一回合不能估计可靠成功率；短程 ACT 与公开预训练 DP 不构成同预算算法优劣比较。
