# Diffusion Policy 阶段收尾

2026-10-13，DP0–DP8 按调整后的“机制学习与有界验证”主线收尾。这里总结项目证据与学习边界，不是完整论文性能复现，也不声明所有知识点已独立书面验收。

## 主线已经连接起来

- 数据与训练：专家 episode → 合法时间窗与 batch → 归一化 → 随机时间步和噪声 → 条件 UNet 预测 → 噪声 MSE → 外部 optimizer 更新。
- 推理与控制：最新观测 → 视觉编码与条件 → 高斯动作块 → 多次 UNet／scheduler 更新 → 选当前执行片段 → 反归一化、缓存 → env.step → 新观测。
- 方法角色：ResNet／SpatialSoftmax 提供视觉表征，时间嵌入表示噪声等级，FiLM 调制动作内部特征，时序 UNet 联合处理动作关系；扩散是生成方法，receding horizon 是执行与反馈的组织方式。
- 外部知识笔记已整理模块层级、数据流、训练恢复、采样配置、BC／多模态、方法—问题对应及最小 Flow Matching 衔接。知识笔记不复制到本仓库，也不作为运行证据。

## 关键理解检查的范围

| 主题 | 对话中完成的引导式确认 |
| --- | --- |
| 训练监督 | 专家动作构造干净样本，MSE 比较预测噪声与实际加入的同一份噪声 |
| 条件注入 | FiLM 的视觉特征是条件来源，被调制的是动作内部特征；该区分经过提示纠正 |
| 缓存与反馈 | 新观测并不使非空动作队列触发 UNet；闭环新观测由模型刚执行的动作产生 |
| 完整续训 | 只恢复权重、重新创建 Adam／随机序列／数据起点不算原样续训 |
| 验证与配置 | 比较 checkpoint 要控制条件；配置字段不自动创建调度器，推理还需核对实际运行属性 |
| 实验结论 | 轨迹变化不等于控制变量失败；接口自检不等于任务成功，成功次数也不等于预测网络变强 |
| 未知根因 | 验证 MSE 下降而闭环失败，不能直接认定训练不足或唯一代码错误 |
| 多模态 | 改回仅输入观测、直接输出唯一动作并做动作 MSE，会移除随机迭代生成机制 |
| Flow Matching 入口 | 识别监督目标为生成路径速度；本轮只做入门衔接，不代表该方法已完整掌握 |

其余概念已讲解和整理，但没有对每个问题做无提示的独立书面测试。后续独立应用仍是检验理解的机会。

## 已有证据与尚未证明的能力

- [DP5 运行记录](dp5_verification.md)：固定 batch 学习、200 步真实训练、有限验证子集与完整恢复已验证；本地模型 seed 0 的闭环失败，不能写成可靠任务策略。
- [DP6 协议](dp6_training_protocol.md)：区分真实设置、候选学习率／模型选择规则与未执行预算，不因文档描述而声明候选方案已经启用。
- [DP7 配对评测](dp7_inference_steps.md)：同一公开预训练模型、100/50 步、5 对 seeds；成功 3/5 与 5/5，稳态平均规划耗时 1317.90/655.69 ms。
- DP7 的小样本观察不证明 50 步普遍最优，也不证明实时控制或真机能力；不能算成本地短程训练的成果。
- 保存恢复检查证明约定计算状态可以继续，不证明策略质量；专家窗口的噪声误差不覆盖模型自己访问的全部闭环状态。
- 完整验证集泛化、从头训练到稳定任务表现、正式多训练 seed 性能复现、ACT 对照、跨任务及真机验证均未完成。失败原因仍可保持未知。
